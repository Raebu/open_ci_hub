# Engineering audit — 19 October 2026

Audit of the **public** `Raebu/open_ci_hub` `main` tree following the initial import. This records observed code and offline tests, **not** a successful provider deployment.

## Verified

- Source corresponds to the existing v4 local package; 57 original Python tests passed.
- The GitHub Actions test workflow is `workflow_dispatch` only, targeting `self-hosted, linux, local-ci`; there were zero recorded workflow runs when checked. Do not switch to paid hosted minutes as a workaround.
- A subsequent change adds a GitHub runner bootstrap and three targeted tests. 60 local tests pass, plus JavaScript syntax and Python compilation.

## Changes in this patch

1. Docker-based GitHub runner now keeps the image's executable assets separately and bootstraps them into persistent state before both registration and start. It does not install a host Docker socket.
2. Registration uses the service entrypoint rather than bypassing bootstrap.
3. Adds offline tests for first-run bootstrapping and preservation of registered state across restarts.
4. Clarifies that Docker normally initialises new named volumes automatically and that runner updates with pre-existing volumes require planned maintenance.

## Remaining release gates (not yet verified)

- **Blocking:** Docker image build and real GitHub/GitLab/CircleCI registration + job execution on a suitable PC. The local environment has neither Docker daemon nor the provider CLIs.
- **Blocking:** Isolate runners for untrusted repository code; do not enable arbitrary external PRs on self-hosted runners. The current project is not a multi-tenant code sandbox.
- **High:** Tailscale identity headers are accepted only through loopback with `.ts.net` host; another process on the same PC could forge those headers. Treat the PC host as trusted and commission a hardened reverse-proxy authentication design before public multi-user deployment.
- **Medium:** GitLab uses a `shell` executor **inside the runner container**; the default image is not a general language/build toolchain. Validate representative jobs, document/install dependencies, or design an appropriately isolated executor.
- **Medium:** CircleCI registration and native machine-agent operation remain unverified; service and plan limits still apply.
- **Medium:** The dashboard is a local-first UI. CLI sign-in is not a hosted account service, and remote access requires an online PC and explicitly configured private Tailscale Serve.
- **Medium:** Add automatic signed runner-image update workflow, backup/recovery and runner deregistration.
