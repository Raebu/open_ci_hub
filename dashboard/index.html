Important: onboarding adds a smoke workflow; it does not silently migrate existing jobs. Existing hosted workflows can still consume paid minutes until reviewed and changed. Never run untrusted PR code on a persistent worker.

Host terminal

New interactive desktop-user terminal session, accessible on the phone only when specifically authorised on the PC.

This is not the actual visible KDE Konsole window. It is an interactive PTY running on the PC. No root permissions are granted by Open CI Hub; your user account still determines what the shell can do. Sessions close automatically.

Host agent and owner permission required.

CI internet access

            
Per-project policy. Offline by default; approved Full mode uses a public-web gateway while Docker remains network-none.

            
          

          

          
Full here means public HTTP and HTTPS via ports 80/443. Private networks, cloud metadata endpoints and all direct container sockets stay blocked. An owner-controlled 0600 manifest enables trusted projects; this screen cannot bypass that policy.

Builds run on authorised hardware. Cloud retries are blocked.

            
          

          

          

        


        

          
Deployments & release evidence

            
Approved environments, exact release commits, previous versions and audit history. Read-only; production actions require independent approval.

            
          

          

          
No deployment is assumed healthy from a green hosted workflow. Real health receipts and staging gates are required. Secrets and raw release logs are never shown here.

        

        

          
Mission cockpit · Background work

            
Independent browser and fixed-task jobs. Your KDE session stays separate; the human has priority.

            

          

          
Pause, resume and cancel are limited to missions without an active step, and require confirmation. Unsafe or interrupted jobs remain blocked for reconciliation. New missions still require local CLI approval; no arbitrary shell commands or automatic phone enrolment.

        

        

          
My computers

            
Switch between separately authorised PCs over private Tailscale HTTPS. Each PC retains its own runner, terminal and deployment approvals.

            
          

          

          

            
            
            

          

          
Remote health checks only verify the HTTPS dashboard endpoint. They do not prove CI or shell access, and registration never gives one PC credentials to control another. Each PC needs its own host agent and Tailscale Serve configuration.
